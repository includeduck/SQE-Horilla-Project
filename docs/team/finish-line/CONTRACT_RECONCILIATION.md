## Chosen contract and discrepancies
| Dimension | Evidence / resolution |
|---|---|
| Swagger dialect/defaults | Normalize Swagger {id} to actual resolver {pk}; compare semantics, not textual equality. Generic Swagger path types, missing bodies and default 200/204 statuses do not override active int converters, serializers or explicit source responses. Per-operation comparison is machine-readable. |
| Added scope | AvailableLeave assignment list/create/detail/update/delete, leave-type reference list and employee-specific available-type list are necessary assignment/reference operations. Existing FR-01..10 and BR-01..04 identifiers remain stable. |
| Roles | Use independent normal employee, approver and outsider users; grant exact permissions for administrative operations. Cancel is an employee operation; assignment has AvailableLeave record identity and no leave-request status. Positive missing-ID outcomes differ by view: self guards commonly return 400, lookup views 404. Generic delete probes with ungranted delete permissions returned 403 before lookup; this is not a fully authorized missing-ID oracle. Noninteger path tokens returned routing 404. |
| Allocation serializers | Create requires requested_days; update allows omission/null as declared by its serializer. Employee is injected in self endpoints. Writable optional non-null is_active was absent from the old spec and is now generated (five self-update smoke cases added). Setting false persists the row and excludes it from the manager's default active-only list; the consumer must assert stable persisted identity plus explicit inactive-list readback instead of mistaking invisibility for deletion. Read-only id/creator/modifier inputs are injection-integrity plans, not writable fields. No positive minimum or arbitrary finite maximum was invented. |
| Assignment collections | ManyRelatedField alone reports allow_empty, but custom validate_employee_ids / validate_leave_type_ids reject empty collections. Preserve minItems 1. Bind real Employee/LeaveType IDs, repeated-form keys and cartesian/idempotence postconditions. Update available_days is required; carryforward_days optional; neither gains invented bounds. |
| Dates / duration | Falsy end_date is normalized to start_date in create/update views. Same-day breakdown, overlap, positive effective duration, employee holiday ownership, company/holiday double exclusion and forecast/carry cap are relational assertions for Prompt 3. A date-order schema predicate alone is not a business oracle. |
| Pagination / filters | page_size parses positive integers, defaults 20 on invalid/nonpositive and clamps 100. A null query value can be omitted by Requests. Groupby uses stock PageNumberPagination, so its page_size handling differs. Invalid django-filter forms may produce an unfiltered .qs instead of HTTP 400. Inventory records each actual form field, lookup and reference/number/date/bool/choice/string partition plan. |
| Files / media | Actual parsers accept JSON, URL-encoded and multipart. Canonical media declarations are explicit, with x-generator-media-type selecting one generated representation. Alternative media, malformed bodies, whole-body omission/null/array/scalar and unsupported types remain mandatory consumers. JSON null and multipart omission are distinct; descriptors must become real bytes. Filename bound is source max_length 100, not an invented file-byte limit. |
| Creator identity | LeaveRequest.created_by points to Employee; allocation/base creator fields point to HorillaUser. Assertions must not exchange these IDs. |
| Rejection reason | Action helper ignores missing/null/nonstring/blank, strips text and truncates to 1000. LeaveRequest.reject_reason model max_length is 255; allocation reason is unbounded TextField. SQLite acceptance alone does not resolve production length compatibility: Prompt 3 must assert normalization/persistence and reproduce any defect before a minimal fix. |
| Accepted policies | Existing OD-01 terminal cancelled-leave refusal and OD-02 identical pending allocation identity are preserved. Actual strict regressions already passed. The historical owner xfail suggestion is not applied; no required assertion is skipped or weakened. |
